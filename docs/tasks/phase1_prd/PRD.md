# Integrated Document Environment Phase1 PRD

- **문서 상태:** Phase1 제품 요구사항
- **대상 조직:** 뉴다이브
- **대상 사용자:** 뉴다이브 임직원
- **제품 성격:** 소프트웨어 의료기기 개발을 위한 사내 GMP 문서 작업 환경

## 1. 배경과 문제

뉴다이브의 GMP 문서는 주로 DOCX와 PDF로 존재하며, 문서 간 계층·의미·인용·스크린샷 등 여러 연결이 있다. 한 문서가 바뀌면 다른 문서, 제품 구성 요소, 테스트 근거도 함께 검토하거나 수정해야 하지만 현재 이러한 연결 정보는 구조화되어 있지 않다.

문서의 담당자는 여러 명일 수 있고 작성, 검토, 승인 과정이 필요하다. 동시에 사용자가 제공한 폰트, 글씨 색, 표 구조, 여백, 줄 간격, 글자 크기 등 모든 서식은 절대 변경되어서는 안 된다.

Phase1은 범용 문서 편집기를 새로 만드는 대신, 변경 요청과 수정안, 문서 관계와 영향, 제품·검증 근거, 협업과 승인, 외부 편집 결과의 서식 검증을 한 작업 흐름으로 통합한다.

## 2. 목표

뉴다이브 임직원이 기존 GMP 문서의 원본 서식을 보존하면서 변경 요청과 수정안을 검토하고, 문서 관계 및 제품·검증 근거의 변경 영향을 사람의 최종 확정 아래 관리하며, 문서별 승인 흐름과 영구 변경 이력을 운영할 수 있게 한다.

Phase1의 제품 요구사항은 다음 잠금 의도를 보존한다.

- `artifact:phase1-prd`: Phase1 구현 기능과 제외 기능이 명확한 `./PRD.md`
- `surface:document-workspace`: GMP 문서를 편집·검토하고 연관 정보를 확인하는 사내 작업 화면
- `integration:docx-pdf`: DOCX/PDF 입력 및 DOCX/PDF 산출 경계
- `integration:product-evidence`: 앱·DB·코드·클라우드 설정·테스트 결과와 문서의 연결 경계
- `constraint:internal-only`: 뉴다이브 임직원만 사용하는 사내 도구
- `constraint:absolute-format-fidelity`: 사용자가 제공한 문서 양식과 모든 서식을 절대 변경하지 않음
- `constraint:prd-no-technical-design`: PRD에는 상세 구현 방법과 명확한 데이터 구조 정의를 포함하지 않음

## 3. 제품 원칙

1. **원본과 서식 무결성:** 원본 파일은 보존하며 미해결 서식 차이가 있는 결과는 최종 완료하거나 산출할 수 없다.
2. **사람의 최종 책임:** 시스템이 만든 수정안, 관계, 영향, 근거 후보는 참고 정보이며 사용자가 확정하기 전에는 사실이나 승인 결과가 아니다.
3. **외부 편집 경계:** 실제 문서 내용 편집은 외부 도구에서 수행한다. IDE는 변경 요청, 수정안 검토, 외부 결과 재수집, 영향 관리, 검증과 승인을 담당한다.
4. **감사 가능성:** 승인 흐름과 진행 중 변경은 이유와 이력을 보존하여 이후에 검토할 수 있어야 한다.
5. **비기술 제품 요구:** 이 문서는 사용자 결과와 제품 경계를 정의하며 기술 아키텍처, 알고리즘, 저장 방식, API 또는 확정 데이터 모델을 정의하지 않는다.

## 4. 사용자와 역할

- **문서 작업자:** 변경 요청을 확인하고 외부 도구에서 문서를 수정한 뒤 결과를 다시 등록한다.
- **검토자:** 수정안, 문서 관계·영향 후보, 제품·검증 근거, 서식 비교 결과를 검토한다.
- **단계 담당자:** 문서별로 구성된 단계에서 문서를 검토하고 단계 승인을 수행한다.
- **문서 흐름 구성자:** 문서별 승인 단계의 이름, 담당자와 순서를 구성한다.

한 사용자가 문서에 따라 여러 역할을 맡을 수 있다. Phase1은 고정된 전사 승인 체계를 강제하지 않고 문서별 흐름을 지원한다.

## 5. 제품 용어

- **수정안 수락:** 시스템이 제안한 변경 내용을 외부 편집 대상으로 채택하는 행위다. 문서 단계 승인이나 문서 최종 완료를 뜻하지 않는다.
- **문서 단계 승인:** 문서별 승인 흐름의 특정 단계를 담당자가 완료하는 행위다.
- **문서 최종 완료:** 모든 필수 단계와 검토 조건을 통과해 문서 작업이 끝난 상태다.
- **승인 산출:** 문서 최종 완료 조건을 충족한 결과물을 허용된 동일 형식으로 내보내는 행위다.
- **후보:** 시스템이 제시하지만 사용자가 확정하기 전까지 참고 상태로 남는 수정안, 관계, 영향 또는 근거 연결이다.
- **오래됨 가능성:** 문서나 연결 대상이 바뀌어 기존 근거를 다시 검토해야 하는 상태다.

## 6. Phase1 사용자 여정

### 6.1 문서 등록과 지원 여부 확인

1. 사용자가 DOCX 또는 PDF를 등록한다.
2. 시스템은 원본 파일을 변경하지 않은 상태로 보존한다.
3. 편집 가능한 DOCX, 텍스트 PDF, 스캔 PDF는 등록과 분석·검토를 지원한다.
4. 암호화되거나 손상된 파일은 처리하지 않고 지원하지 않는 이유를 알린다.
5. 스캔 PDF는 분석·검토에서 여정이 끝나며 외부 편집 왕복, 형식 비교, 승인 산출로 진행하지 않는다.

### 6.2 변경 요청과 변경 전 검토

1. 사용자가 문서에 변경 요청을 등록한다.
2. 시스템은 수정안과 관련 문서·제품·검증 근거 후보를 제시한다.
3. 사용자는 변경 전에 관계, 영향과 근거 최신성을 검토한다.
4. 사용자는 수정안을 수락, 반려하거나 다시 제안하도록 요청한다.
5. 수정안 수락은 외부 편집의 시작 조건일 뿐 문서 단계 승인이 아니다.

### 6.3 외부 편집과 동일 형식 결과 재수집

1. 편집 가능한 DOCX는 외부 도구에서 수정한 DOCX로 다시 등록한다.
2. 텍스트 PDF는 외부 도구에서 수정한 PDF로 다시 등록한다.
3. DOCX를 PDF로 또는 PDF를 DOCX로 변환하는 경로는 지원하지 않는다.
4. 스캔 PDF는 외부 편집 결과를 다시 등록하는 경로를 지원하지 않는다.

### 6.4 형식·영향·근거 재검토

1. 지원되는 외부 편집 결과에 대해 시스템이 원본 대비 서식 차이를 자동 검사한다.
2. 사용자는 원본과 결과물의 시각 비교 화면에서 차이를 확인한다.
3. 시스템은 변경된 내용에 대해 문서 관계·영향과 제품·검증 근거 후보를 다시 제시한다.
4. 문서나 연결 대상 중 어느 한쪽이 변경되면 관련 근거를 오래되었을 가능성이 있다고 표시한다.
5. 사용자는 후보와 오래됨 상태를 검토하고 확정하거나 해제한다.
6. 미해결 서식 차이가 있으면 외부 수정, 동일 형식 결과 재수집, 자동 재검사, 시각 비교를 반복한다.

### 6.5 문서 단계 승인과 최종 완료

1. 문서별로 정의된 순서와 담당자에 따른 단계 승인은 `REQ-COL-002`, `REQ-COL-006`을 따른다.
2. 각 단계 승인 또는 최종 완료 전의 반복 영향·최신성 검토는 `REQ-IMP-005`, `REQ-EVD-005`, `REQ-EVD-006`을 따른다.
3. 후보 확정과 형식 검증 완료 게이트는 `REQ-IMP-004`, `REQ-EVD-004`, `REQ-FMT-004`, `REQ-FMT-005`를 따른다.
4. 한 단계의 승인은 다음 단계로 진행할 수 있다는 뜻이며 `REQ-CHG-004`에 따라 문서 최종 완료와 구분된다.
5. 모든 필수 단계를 완료하고 나머지 조건을 충족하면 문서를 최종 완료하고 동일 형식으로 산출한다.

## 7. 입력·왕복·산출 능력 경계

| 입력 유형 | 등록 | 분석·검토 | 외부 결과 재수집 | 원본 대비 형식 비교 | 허용 산출 |
|---|---|---|---|---|---|
| 편집 가능한 DOCX | 지원 | 지원 | 외부 편집된 DOCX를 DOCX로 재수집 | 자동 검사와 시각 비교 모두 지원 | 미해결 서식 차이 0인 DOCX |
| 텍스트 PDF | 지원 | 지원 | 외부 편집된 PDF를 PDF로 재수집 | 자동 검사와 시각 비교 모두 지원 | 미해결 서식 차이 0인 PDF |
| 스캔 PDF | 지원 | 내용 분석·검토 전용 | 미지원 | 미지원 | 미지원 |

- DOCX→PDF 및 PDF→DOCX 교차 형식 변환은 Phase1에서 지원하지 않는다.
- 편집 가능한 DOCX와 텍스트 PDF의 두 경로는 각각 독립적으로 완결된 승인 산출 경로다.
- 지원되는 산출은 자동 검사와 시각 비교를 모두 완료하고 미해결 서식 차이가 없어야 한다.

## 8. 기능 요구사항

### 8.0 사내 접근 경계

- **REQ-ACC-001:** 뉴다이브 임직원만 Phase1 문서 작업 환경에 접근할 수 있어야 하며 외부 사용자는 접근할 수 없어야 한다.

### 8.1 문서 등록과 원본 보존

- **REQ-DOC-001:** 사용자는 편집 가능한 DOCX, 텍스트 PDF, 스캔 PDF를 등록할 수 있어야 한다.
- **REQ-DOC-002:** 시스템은 등록된 원본 파일을 변경하지 않은 상태로 보존해야 한다.
- **REQ-DOC-003:** 암호화되거나 손상된 문서는 처리를 거부하고 사유를 사용자에게 알려야 한다.
- **REQ-DOC-004:** 시스템은 입력 형식에 따라 지원되는 분석, 외부 편집 왕복, 비교와 산출 범위를 명확히 보여야 한다.

### 8.2 변경 요청과 수정안

- **REQ-CHG-001:** 사용자는 문서에 변경 요청을 등록하고 담당자별 처리 상태를 확인할 수 있어야 한다.
- **REQ-CHG-002:** 시스템은 요청과 문서 문맥을 바탕으로 수정안을 후보로 제시해야 한다.
- **REQ-CHG-003:** 사용자는 수정안을 수락, 반려 또는 재요청할 수 있어야 한다.
- **REQ-CHG-004:** 수정안 수락은 문서 단계 승인이나 최종 완료와 구분되어야 한다.

### 8.3 외부 편집 결과와 형식 보존

- **REQ-FMT-001:** 편집 가능한 DOCX는 DOCX로, 텍스트 PDF는 PDF로 외부 편집 결과를 재수집해야 한다.
- **REQ-FMT-002:** 시스템은 지원 경로의 원본과 결과물 사이에서 폰트, 글씨 색, 표 구조, 여백, 줄 간격, 글자 크기 등 제공된 모든 서식의 차이를 자동 검사해야 한다.
- **REQ-FMT-003:** 사용자는 원본과 결과물을 시각적으로 비교할 수 있어야 한다.
- **REQ-FMT-004:** 자동 검사와 시각 비교는 서로 대체하지 않으며 둘 다 완료되어야 한다.
- **REQ-FMT-005:** 미해결 서식 차이가 하나라도 있으면 단계 승인 완료, 문서 최종 완료와 승인 산출을 차단해야 한다.
- **REQ-FMT-006:** 차이가 발견되면 외부 수정부터 재수집, 자동 재검사와 시각 비교를 반복할 수 있어야 한다.
- **REQ-FMT-007:** DOCX↔PDF 변환과 스캔 PDF의 편집 왕복·비교·산출을 제공해서는 안 된다.
- **REQ-FMT-008:** 모든 완료 게이트를 통과한 편집 가능한 DOCX는 DOCX로, 텍스트 PDF는 PDF로 승인 산출할 수 있어야 한다.

### 8.4 문서 관계와 변경 영향

- **REQ-IMP-001:** 시스템은 계층, 의미 연관, 인용, 다른 문서의 스크린샷 등 문서 관계 후보를 제시해야 한다.
- **REQ-IMP-002:** 관계 후보에는 관련 문서, 관련 위치와 연결 이유가 포함되어야 한다.
- **REQ-IMP-003:** 문서 변경 시 관련 문서별 수정 필요 여부와 수정안 후보를 제시해야 한다.
- **REQ-IMP-004:** 모든 관계와 영향 후보는 사용자가 최종 확정하기 전까지 참고 상태여야 한다.
- **REQ-IMP-005:** 영향 검토는 수정안 수락 전, 외부 결과 재수집 후, 단계 승인 또는 최종 완료 전에 반복할 수 있어야 한다.

### 8.5 제품·검증 근거

- **REQ-EVD-001:** 사용자가 업로드한 이미지·파일과 직접 입력한 설명을 문서 근거로 다뤄야 한다.
- **REQ-EVD-002:** 앱 클라이언트, 웹 클라이언트, 서버 코드, DB와 클라우드 설정의 스냅샷·설명을 근거 후보 범위에 포함해야 한다.
- **REQ-EVD-003:** API 호출을 포함한 테스트 결과, 캡처와 설명을 근거 후보 범위에 포함해야 한다.
- **REQ-EVD-004:** 시스템은 문서와 근거의 연결 후보를 제시하고 사용자가 확정하게 해야 한다.
- **REQ-EVD-005:** 문서 또는 연결 대상이 변경되면 근거를 오래되었을 가능성이 있다고 표시해야 한다.
- **REQ-EVD-006:** 사용자는 검토를 마친 오래됨 표시를 해제할 수 있으며 이후 관련 변경 시 다시 검토 대상으로 돌아가야 한다.

### 8.6 협업과 승인 흐름

- **REQ-COL-001:** 시스템은 담당자별 수정 요청, 의견과 처리 상태를 추적해야 한다.
- **REQ-COL-002:** 사용자는 문서별로 임의 이름의 승인 단계를 만들고 각 단계 담당자와 순서를 정할 수 있어야 한다.
- **REQ-COL-003:** 조건 분기, 병렬 승인과 대리 승인은 Phase1에서 제공하지 않는다.
- **REQ-COL-004:** 승인 시작 후에는 미완료 단계만 변경할 수 있고 완료 단계는 변경할 수 없어야 한다.
- **REQ-COL-005:** 진행 중 흐름 변경 시 사유, 변경자, 변경 시각과 변경 전후 이력을 영구 보존해야 한다.
- **REQ-COL-006:** 문서 단계 승인은 해당 단계의 담당자만 정해진 순서에 따라 수행할 수 있어야 한다.

### 8.7 최종 진행 게이트

- **REQ-GAT-001:** 수정안·관계·영향·근거 후보 중 수락·확정·거절되지 않은 항목이 하나라도 있으면 문서 단계 승인 완료, 문서 최종 완료와 승인 산출을 차단해야 한다.

## 9. 오류와 차단 경험

- 미지원 파일은 실패 이유와 지원 범위를 함께 안내한다.
- 다른 형식으로 재수집된 결과는 지원 경로가 아님을 알리고 비교·승인 산출로 진행하지 않는다.
- 미해결 서식 차이가 있으면 어떤 차이가 남았는지 보여 주고 외부 수정부터 다시 시작하도록 안내한다.
- 사용자가 확정하지 않은 후보는 문서 최종 완료의 근거로 사용하지 않는다.
- 오래됨 가능성이 남은 근거는 재검토 필요 상태로 표시한다.
- 완료된 승인 단계를 바꾸려는 시도는 차단한다.

## 10. Phase1 포함 범위

- 뉴다이브 임직원 전용 문서 작업 화면
- 편집 가능한 DOCX와 텍스트 PDF의 동일 형식 외부 편집 왕복, 비교와 산출
- 스캔 PDF 등록 및 내용 분석·검토
- 변경 요청, 수정안 후보, 수락·반려·재요청
- 문서 관계 및 변경 영향 후보와 사용자 확정
- 제품·검증 근거 후보, 오래됨 표시와 사용자 해제
- 문서별 승인 단계 이름·담당자·순서 구성
- 미완료 단계 변경과 영구 변경 이력
- DOCX/PDF 승인 산출 전 절대 서식 보존 검증

## 11. 명시적 제외 범위

- IDE 내부의 범용 DOCX/PDF 직접 편집기
- 암호화되거나 손상된 DOCX/PDF 처리
- 스캔 PDF의 외부 편집 결과 재수집, 형식 비교와 승인 산출
- DOCX→PDF 또는 PDF→DOCX 교차 형식 변환
- 관계·영향·수정안·근거 후보의 무인 자동 확정
- 조건 분기, 병렬 승인, 대리 승인 등 고급 승인 자동화
- 외부 고객용 멀티테넌트 상용 서비스
- 상세 기술 아키텍처, 라이브러리, 프로토콜, 알고리즘, 저장 방식과 화면 구현 명세
- 확정 데이터 모델, 필드 스키마와 API 계약

## 12. 수용 기준

- **AC-DOC-001:** 사용자는 세 지원 입력 유형을 등록할 수 있고 암호화·손상 파일은 명확한 사유와 함께 거부된다.
- **AC-DOC-002:** 등록 이후 원본 파일이 변경되지 않은 상태로 남는다.
- **AC-DOC-003:** 스캔 PDF는 분석·검토까지만 진행되며 왕복·비교·산출 동작이 노출되지 않는다.
- **AC-ACC-001:** 뉴다이브 임직원은 문서 작업 환경에 접근할 수 있고 외부 사용자의 접근은 거부된다.
- **AC-CHG-001:** 사용자가 변경 요청을 등록하고 수정안을 수락·반려·재요청할 수 있다.
- **AC-CHG-002:** 수정안 수락만으로 문서 단계 승인이나 최종 완료가 발생하지 않는다.
- **AC-CHG-003:** 한 단계의 승인 완료는 다음 단계 진행만 허용하며 남은 필수 단계가 있으면 문서 최종 완료가 발생하지 않는다.
- **AC-FMT-001:** DOCX 결과는 DOCX로, 텍스트 PDF 결과는 PDF로만 재수집된다.
- **AC-FMT-002:** 지원 결과는 자동 서식 검사와 원본 대비 시각 비교를 모두 완료해야 단계 승인 완료, 문서 최종 완료 또는 승인 산출로 진행할 수 있다.
- **AC-FMT-003:** 미해결 서식 차이가 있으면 단계 승인 완료, 최종 완료와 승인 산출이 모두 불가능하다.
- **AC-FMT-004:** 외부 수정과 동일 형식 재수집 후 자동 재검사·시각 비교를 반복할 수 있고, 미해결 차이가 없을 때만 차단이 해제된다.
- **AC-FMT-005:** 완료 조건을 충족한 DOCX는 DOCX로, 텍스트 PDF는 PDF로 산출할 수 있다.
- **AC-FMT-006:** DOCX↔PDF 변환과 스캔 PDF 산출은 제공되지 않는다.
- **AC-IMP-001:** 사용자는 관계 후보의 관련 문서·위치·이유를 확인하고 확정 또는 거절할 수 있다.
- **AC-IMP-002:** 사용자는 영향받는 문서별 수정 필요 여부와 수정안 후보를 검토하고 각각 확정 또는 거절할 수 있다.
- **AC-IMP-003:** 영향 후보는 사용자 확정 전까지 참고 상태로 유지된다.
- **AC-IMP-004:** 영향 검토는 변경 전, 재수집 후와 단계 승인·최종 완료 전에 다시 수행할 수 있다.
- **AC-EVD-001:** 업로드 자료, 직접 입력 설명, 제품 구성 요소 스냅샷과 테스트 결과를 근거 후보로 제시하고 사용자가 연결을 확정 또는 거절할 수 있다.
- **AC-EVD-002:** 문서 또는 연결 대상이 변경되면 오래됨 가능성이 표시된다.
- **AC-EVD-003:** 사용자는 오래됨 표시를 검토 후 해제할 수 있고 이후 관련 변경 시 상태가 다시 열린다.
- **AC-EVD-004:** 오래됨 가능성이 남아 있어 필수 최신성 검토가 끝나지 않은 문서는 단계 승인 완료, 문서 최종 완료와 승인 산출로 진행할 수 없다.
- **AC-COL-001:** 담당자별 요청, 의견과 처리 상태를 확인할 수 있다.
- **AC-COL-002:** 문서별 단계 이름, 담당자와 순서를 구성할 수 있다.
- **AC-COL-006:** 조건 분기, 병렬 승인과 대리 승인 구성 또는 실행 동작은 제공되지 않는다.
- **AC-COL-003:** 진행 중에는 미완료 단계만 바꿀 수 있고 완료 단계 변경은 차단된다.
- **AC-COL-004:** 흐름 변경 사유, 변경자, 변경 시각과 변경 전후 이력을 영구적으로 확인할 수 있다.
- **AC-COL-005:** 현재 단계의 지정 담당자가 아닌 사용자 또는 순서를 건너뛴 단계 승인 시도는 차단되며, 올바른 담당자가 현재 단계 승인을 마친 뒤에만 다음 단계로 진행한다.
- **AC-GAT-001:** 미처리 수정안 후보 또는 미확정 관계·영향·근거 후보가 남아 있으면 단계 승인 완료, 문서 최종 완료와 승인 산출이 차단되고, 모든 후보가 수락·확정 또는 거절된 뒤에만 해당 차단이 해제된다.

## 13. 성공 지표

Phase1 운영 초기에는 수치 목표를 임의로 확정하지 않고 다음 항목을 측정 가능하게 한다.

- 변경 요청이 최종 완료되기까지 걸린 시간
- 변경 전후 검토에서 발견된 연관 문서와 근거 후보 수
- 사용자가 수락·거절한 자동 후보 비율
- 서식 차이로 인해 재작업된 횟수와 최종 미해결 차이 수
- 오래됨 표시 후 검토 완료까지 걸린 시간
- 승인 흐름의 단계별 대기 시간과 변경 횟수

목표 수치는 실제 사내 사용 자료를 확보한 뒤 별도로 결정한다.

## 15. Phase1 완료 정의

Phase1 제품은 이 PRD의 포함 범위를 충족하고 모든 수용 기준이 관찰 가능한 사용자 결과로 검증될 때 완료로 본다. 특히 다음 조건은 타협할 수 없는 완료 게이트다.

1. 자동 검사와 시각 비교를 모두 완료한다.
2. 미해결 서식 차이가 없다.
3. 필요한 문서 관계·영향·근거 후보를 사용자가 최종 확정한다.
4. 필요한 문서 단계 승인을 모두 완료한다.
5. DOCX는 DOCX로, 텍스트 PDF는 PDF로만 승인 산출한다.
6. 스캔 PDF와 교차 형식 변환을 산출 경로로 사용하지 않는다.
